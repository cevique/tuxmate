
# TuxMate - Project Instructions

## Project Overview
TuxMate is an educational website for learning Linux,
Linux terminal commands and Bash scripting.

## Mandatory Technology Restrictions
- HTML5 only for markup.
- CSS3 only for styling.
- Vanilla JavaScript only for functionality.
- No React, Vue, Angular or other frameworks.
- No Bootstrap, Tailwind or CSS frameworks.
- No jQuery or JavaScript libraries.
- No npm packages or external dependencies.
- No backend, database or authentication.
- No external APIs without explicit approval.
- No build tools or bundlers.

## Design Direction
- Retro pixel-art RPG aesthetic.
- Inspired by the visual direction of Codedex.io.
- Do not copy its branding, assets or source code.
- Dark navy navigation.
- Yellow/orange pixel-style buttons.
- Pixel-art landscapes and characters.
- Consistent Tux and Byte mascots.
- Responsive desktop, tablet and mobile layouts.
- Readable typography and accessible contrast.

## Architecture
- Multiple independent HTML pages.
- Shared CSS files.
- Modular vanilla JavaScript files.
- Semantic HTML.
- Relative paths for all local assets.
- No inline JavaScript.
- No duplicated navigation styling.

## Functionality
- All navigation links must work.
- All buttons must have actual functionality.
- Quizzes must provide feedback.
- Progress must work without accounts.
- localStorage is optional and must remain local.
- No collection of personal information.

## Bash Playground
- Never execute actual shell commands.
- Never use eval() or Function() for student input.
- Implement a restricted JavaScript-based simulator.
- Use an isolated virtual filesystem.
- Clearly distinguish simulation from actual Bash.
- Unsupported commands must return an informative error.
- Dry-run exercises must have deterministic outputs.

## Development Rules
- Work incrementally.
- Do not generate the entire website in one response.
- Inspect existing files before modifying them.
- Do not overwrite completed functionality unnecessarily.
- Test every page after implementation.
- Do not invent educational facts.
- Keep code readable and suitable for first-semester
  university students to explain and maintain.
